# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

`Claude-forex-agent` is an AI-powered foreign exchange (forex) assistant built on Anthropic's Claude models. It supports two modes:

- **CLI REPL** (`main.py`) — synchronous tool-use loop, runs entirely locally.
- **Chat UI** (`server.py`) — FastAPI web server backed by an Anthropic Managed Agent session that streams responses in real time.

## Commands

```bash
# Install dependencies (creates .venv automatically)
uv sync

# Run the interactive CLI REPL
uv run python main.py

# --- Managed Agent + Chat UI (one-time setup, then start server) ---

# 1. Create the Managed Agent and Cloud Environment on Claude platform
uv run python setup_agent.py --write   # appends IDs to .env automatically

# 2. Start the web server
uv run uvicorn claude_forex_agent.server:app --reload --port 8000
# Open http://localhost:8000 in your browser

# Lint
uv run ruff check .
uv run ruff check --fix .

# Tests
uv run pytest tests/ -v

# Run a single test
uv run pytest tests/test_rates.py::test_get_exchange_rate_returns_rate -v
```

## Environment Variables

Copy `.env.example` to `.env` and set:

| Variable | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | Anthropic API key for Claude |
| `MANAGED_AGENT_ID` | Agent ID generated by `setup_agent.py` |
| `MANAGED_AGENT_VERSION` | Agent version generated by `setup_agent.py` |
| `MANAGED_AGENT_ENV_ID` | Environment ID generated by `setup_agent.py` |

The Managed Agent variables are only required for the Chat UI (`server.py`). The CLI REPL (`main.py`) only needs `ANTHROPIC_API_KEY`.

## Architecture

```
main.py                              # CLI REPL entry point
setup_agent.py                       # One-time: create Managed Agent + Environment on Claude platform
src/claude_forex_agent/
  agent.py                           # ForexAgent — synchronous Claude tool-use loop (REPL mode)
  managed_agent.py                   # ForexManagedAgent — Managed Agent session with streaming
  server.py                          # FastAPI app + embedded chat UI (web mode)
  tools/
    registry.py                      # Maps tool names → handlers + exports TOOL_SCHEMAS
    rates.py                         # get_exchange_rate (Frankfurter public API)
    currencies.py                    # list_currencies
    convert.py                       # convert_amount
    historical.py                    # get_historical_rates
tests/
  test_agent.py                      # ForexAgent unit tests (mocked client)
  test_rates.py                      # Tool tests using pytest-httpx mocks
  test_currencies.py
  test_convert.py
  test_historical.py
```

### CLI agent loop (`agent.py`)

`ForexAgent.run(user_message)` implements a synchronous tool-use loop:
1. Send messages to Claude with `TOOL_SCHEMAS`.
2. If `stop_reason == "end_turn"`, return the text response.
3. Otherwise dispatch each `tool_use` block via `_dispatch_tool` → `registry`.
4. Append assistant + tool results to the message list and repeat.

Conversation history is preserved in `self.history` across `run()` calls; `reset()` clears it.

### Managed Agent session (`managed_agent.py`)

`ForexManagedAgent.stream_response(session_id, user_message)` is a generator that:
1. Opens an SSE stream (stream-first pattern) then sends the user message.
2. Yields `("text", chunk)` tuples as the agent streams its reply.
3. On `agent.custom_tool_use` events, calls the registered handler locally and loops.
4. Stops on `session.status_idle` (no more tool calls) or `session.status_terminated`.

Sessions are stateful on the Claude platform — each session maintains full conversation history automatically.

### Chat UI (`server.py`)

FastAPI routes:
- `GET /` — HTML chat page (embedded in `CHAT_HTML`).
- `POST /api/session` — creates a Managed Agent session and returns its ID.
- `POST /api/chat` — accepts `{session_id, message}`, streams `text/event-stream` SSE events.

The browser creates a session on page load, stores the `session_id` in memory, and streams
responses using `fetch()` + `ReadableStream` (no EventSource; supports POST).

### Adding a new tool

1. Create `src/claude_forex_agent/tools/<name>.py` with a handler function and its `*_SCHEMA` dict.
2. Register both in `tools/registry.py` (`registry` dict and `TOOL_SCHEMAS` list).
3. Both the CLI loop and the Managed Agent pick it up automatically.

### HTTP calls

Tools use `httpx` directly (synchronous). Use `pytest-httpx`'s `httpx_mock` fixture to mock network calls in tests rather than hitting live APIs.
